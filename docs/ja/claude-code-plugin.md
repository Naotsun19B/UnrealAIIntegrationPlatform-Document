# Claude Code Plugin

Claude Code から UAIP の HTTP API に**直接**アクセスし、UE Editor プロジェクトを操作・観測・テストできる
8 つの Claude Code スキル（`/uaip:*`）です。**MCP サーバーの設定も MCP Bridge のインストールも不要**です。
各スキルは同梱の事前承認済み Python スクリプトを 1 本実行し、対応するコマンドを探してパラメータスキーマを読み、
このプロジェクトのエディタに対して実行します — パラメータ名を推測することも、モデルが直接シェルコマンドを
書くこともありません。

このページでは本プラグインのインストール・検証・実行方法と、[MCP Bridge](connections.md#mcp-bridge) との
使い分けを説明します。内部で話している先のトランスポートについては
[接続方法 → HTTP API](connections.md#http-api製品版) を参照してください。

---

## 動作環境

- **Windows (Win64) のみ。**
- **Python 3.10 以降**（`PATH` 上で `python` として実行できること）。Windows では、`PATH` 上に実体の
  Python が無い場合、`python` を実行すると Microsoft Store のプレースホルダー（"app execution alias"）が
  何もせずに開くことがあります。スキルの最初のコマンドが何も起きていないように見える場合は、自分で
  `python --version` を実行し `Python 3.10` 以降と表示されるか確認してください。
- **UAIP 1.2.0 以降**が、HTTP API を有効にして動作していること（MCP 専用モードやデモ版では不可 —
  詳細は下記 [本プラグインと MCP Bridge の使い分け](#本プラグインと-mcp-bridge-の使い分け) を参照）。

## インストール

1. リリース zip と、同梱の `.sha256` ファイルを、このリポジトリの [Releases](../../../releases)
   （タグ `ClaudeCodePlugin-v<X.Y.Z>`、アセット `UAIP-ClaudeCodePlugin-<X.Y.Z>.zip`）からダウンロードし、
   検証します — 下記 [ダウンロードの検証](#ダウンロードの検証) を参照。
2. zip を、UE プロジェクトフォルダの**外**、Claude Code の作業ディレクトリの**外**、`additionalDirectories`
   設定に列挙したパスの**外**の場所へ展開してください — 自分だけが書き込め、削除する予定のない恒久的な
   フォルダにします（例: `%USERPROFILE%\ClaudePlugins\`）。これは重要です。展開先の `UAIPClaudeCodePlugin`
   フォルダは、Claude Code が事前承認済みスクリプトを実際に実行する場所なので、このフォルダに書き込める者は
   誰でもそれらの事前承認済みコマンドの中身を書き換えられます。このフォルダへの書き込み権限は、コード実行の
   承認と同等のものとして扱ってください。
3. Claude Code で `/plugin marketplace add <展開した UAIPClaudeCodePlugin フォルダのパス>` を実行します。
4. `/plugin install uaip@uaip-tools` を実行します。
5. Claude Code を再起動します。8 つの `/uaip:*` スキルが一覧に表示されるはずです。

## ダウンロードの検証

各リリースには zip と並んで `.sha256` ファイルが公開されており、2 行の内容になっています。

```
<sha-256 の16進数、小文字>  UAIP-ClaudeCodePlugin-<version>.zip
commit <このリリースをビルドしたコミット>
```

同じ SHA-256 は、このページ（下記 [リリースのチェックサム](#リリースのチェックサム)）にも独立した
第二の情報源として記録されています。zip を信頼する前に両方と突き合わせてください。

```powershell
Get-FileHash UAIP-ClaudeCodePlugin-<version>.zip -Algorithm SHA256
```

表示されたハッシュ値は、`.sha256` ファイルの1行目（大文字小文字は区別しない）と、下表に記録した値の
両方と一致する必要があります。

## アップデート・古いリリースへのロールバック

1. 展開先フォルダの中身を**すべて**削除してください。上書きだけのアップデートでは、新しいバージョンで
   削除されたはずの古いファイルが残ってしまうことがあります。
2. 目的のバージョン（アップデートなら最新リリース、ロールバックなら古いリリース）の zip を展開します。
3. Claude Code で `/plugin marketplace update uaip-tools` を実行し、再起動します。

watchdog オプション付きでエディタを起動していた場合（下記 [エディタの起動](#エディタの起動) 参照）、
watchdog は別のバックグラウンドプロセスとして古いスクリプトのまま動き続けます。ただし、見張っていた
エディタの応答が止まってから（待ち受けが消え、クラッシュの印も無い状態が続いてから）数分で自動的に
終了するため、手動で見つけて閉じる必要はありません。待ちたくない場合は、先にエディタを閉じてから
watchdog プロセスを自分で終了させても同じ効果が得られます。

## 旧リリースからの移行

以前の未リリース版は `uaip@local-plugins` という名前でインストールされていました。該当する場合は次の
手順で移行してください。

1. Claude Code で `uaip` プラグインと `local-plugins` マーケットプレイスエントリを無効化・削除します。
2. ディスク上のコピー（通常は `~/.claude/local-marketplace/plugins/uaip`。Windows では
   `%USERPROFILE%\.claude\local-marketplace\plugins\uaip`）を削除します。
3. 上記 [インストール](#インストール) の手順に従って本リリースを導入します。旧いコピーを残したまま
   並行させると、同じスキル名が二重に登録されてしまいます。

## エディタの起動

チャットで依頼するか、スキルを直接実行します。

```
/uaip:launch
/uaip:launch --port 9000
/uaip:launch --enable-scenario
```

- `--port <N>`: 既定のポートではなく、指定したポートでエディタを起動（既に動いている場合はアタッチ）します。
  エディタが起動した後は、動き続けている限り他のスキルが自動的にそのポートを覚えているので、別のポートを
  使いたいとき以外は改めて指定する必要はありません。
- `--enable-scenario`: エディタがシナリオの投入を受け付けるようにします（[シナリオ実行](scenario.md) と
  下記 `/uaip:scenario` スキルを参照）。既に動いているエディタを遠隔で切り替えることはできません —
  一度閉じてから `/uaip:launch --enable-scenario` を再実行してください。

本プラグインはエディタの HTTP API モードを必要とします。**デモ版を含む MCP 専用起動は本プラグインでは
サポートされません** — 詳細は下記 [本プラグインと MCP Bridge の使い分け](#本プラグインと-mcp-bridge-の使い分け)
を参照してください。

## セキュリティ境界

- **確認なしで実行されるもの**: 各スキルは、自分が呼ぶ同梱スクリプト1本と、現在のプロジェクトの
  `Saved/UAIP/temp/` の読み取り・`Saved/UAIP/Requests/` への書き込みという狭い権限だけを事前承認します。
  コマンドを送るスクリプト自体が事前承認されているため、コマンド名ごとに個別の Claude Code の確認なしで
  *任意の* UAIP コマンド名を送信できます。あるコマンドが実際に何をできるかを決める境界は、エディタ自身の
  [Capability 付与と SafetyPolicy](safety.md) であり、Claude Code の承認プロンプトではありません。エディタが
  許可しないコマンドは `CapabilityNotAvailable` または `PolicyViolation` として返り、スキルはこれを報告して
  許可するかどうかを尋ねます（エディタの設定自体をスキルが勝手に変更することはありません）。
- **資格情報の送り先**: どこかへ認証トークンを送る前に、本プラグイン（および、資格情報を設定した場合の
  MCP Bridge も同様）は、対象ポート上のプログラムに対し、本物のエディタだけが読める起動ごとの秘密値を使って
  「このプロジェクトの UAIP エディタである」ことを証明させます — 詳しい仕組みは
  [セキュリティ → Instance proof](security.md#instance-proof) を参照してください。それを証明できないプログラム
  — 別プロジェクトのエディタ、たまたま同じポートを使っている無関係なプログラム、ポートフォワードの中継、
  または 1.2.0 より古いエディタビルド — にはトークンが送られることはありません。該当するスキルはこれを
  接続失敗として報告し、何を確認すべきか（別のポートを選ぶ・エディタを起動する・更新する）を案内します。
- **それでも Claude Code の設定で承認が求められる場合**: 環境によっては既定の作業ディレクトリ読み取り権限が
  無効化されていたり、すべてのルールを明示的に列挙する必要があったりします。スキルが呼ぶスクリプトごとに
  1 ルール、加えて 2 つのディレクトリルールを追加してください（パスは実際の展開先に置き換えてください）。

  ```
  Bash(python "<展開先フォルダ>/plugins/uaip/scripts/exec.py":*)
  Read(Saved/UAIP/temp/**)
  Edit(Saved/UAIP/Requests/**)
  ```

## スキル一覧

| スキル | 内容 |
|---|---|
| `/uaip:uaip` | 入り口: 自然言語のリクエストまたはコマンド名を受け取り、一致するコマンドを探して該当スキルへルーティングする |
| `/uaip:launch` | HTTP API を有効にしてエディタを起動する（ポート指定・シナリオ有効化・クラッシュ/フリーズ watchdog 付きも可） |
| `/uaip:health` | 簡易ヘルスチェック: エディタが応答することと、そのバージョン・負荷を確認する |
| `/uaip:diag` | 資格情報を一切送らずに、到達不能・クラッシュしたエディタを診断する（到達性・TCP ポート・クラッシュマーカー・クラッシュログ） |
| `/uaip:exec` | 任意の UAIP コマンドを1つ実行する: 検索し、パラメータスキーマを読み、実行し、結果と Artifact を報告する |
| `/uaip:capture` | スクリーンショットと状態ダンプ（アクティブウィンドウ、グラフエディタタブ、エディタタブ、Output Log 等） |
| `/uaip:test` | Automation Test または Automation Spec を実行し、Pass / Fail / Error を報告する |
| `/uaip:scenario` | 一連のコマンドを順序付きバッチとして [シナリオ](scenario.md) にまとめて投入し、各ステップの結果を報告する |

## 時間のかかるコマンドの実行

同梱の `exec.py` スクリプトは既定でコマンドの応答を最大 130 秒待ちます — エディタ自身の HTTP 非同期コマンドタイムアウトが 120 秒で、スクリプトはそこに 10 秒の余裕を足しています。大規模な Automation Test の実行など、正当にそれより長くかかるコマンドは、**両側**の待ち時間を同時に延ばす必要があります。片方だけでは、エディタ側では処理が続いているのに呼び出しがタイムアウトとして返ってしまいます。

- **エディタ自身の待ち時間**: `exec.py` の呼び出しに `--timeout N`（1〜1800 の整数）を追加します。これはリクエストのトップレベルフィールド `TimeoutSeconds` として送られ、エディタは既定の 120 秒ではなく最大 `N` 秒まで応答を待つようになります。`exec.py` 自身はその後 `N + 10` 秒だけ応答を待ちます。`--timeout` はシナリオの投入（`/uaip:scenario`）とは併用できません — シナリオは独自の 1800 秒の壁時計上限を持つためです。この HTTP フィールドの詳細は [API リファレンス → リクエスト形式](api.md#2-リクエスト形式)（§2.1）を参照してください。
- **Bash ツール自身の上限**: Bash ツールには `--timeout` に 60 秒を足した値（ミリ秒）を `timeout` として渡してください。上限は 600000 ms（10 分）です。それに近い、またはそれを超える実行には、代わりにバックグラウンドで開始し、完了通知を受けてから出力を読んでください。

`/uaip:test` では、コマンド自身の `TimeoutSec` パラメータ（1〜600、既定 60）も一緒に引き上げてください — これはエディタが**テスト実行自体**に与える上限で、HTTP トランスポートが応答をどれだけ待つかを決めるだけの `--timeout` とは独立しています。`TimeoutSec` はテストに必要な時間に、`--timeout` はそれより少し大きい値（目安として 30 秒ほど多く）に設定します。例：

```bash
python "<展開先フォルダ>/plugins/uaip/scripts/exec.py" "UAIP.Editor.Execution.RunAutomationTest" '{"TestName": "UAIP.Core.", "TimeoutSec": 300}' --timeout 330
```

それでもエディタが応答しない場合、終了コード 4 は**結果が不明であること**を意味します — テストがまだ実行中の可能性があります。同じリクエストを再送せず、失敗と決めつけずに（次回はより大きな `--timeout` で、または `/uaip:diag` で）改めて確認してください。

## 本プラグインと MCP Bridge の使い分け

本プラグインのスキルは、同梱の Python スクリプトを HTTP 経由で直接呼び出します。Claude Code に MCP サーバー
を設定する必要はありません。エディタを直接操作させたい場合、かつ別途 [MCP Bridge](connections.md#mcp-bridge)
をデプロイ・保守したくない場合に、このスキル群を使ってください。

これとは別に、UAIP の MCP Bridge は同じ内部コマンド群を MCP ツールとして公開しており、スクリプトを直接
呼ぶのではなく MCP で話す AI クライアント向けです — これには [Claude Code 自身の MCP クライアント向けページ](clients/claude-code.md)
経由の Claude Code も含まれます。セッションに MCP Bridge も UAIP 向けに設定されている場合、その MCP ツール
は同じエディタに到達し、同じ操作をこのスキル群の代わりに行えます — 両者は代替手段であり、同じエディタ
セッションに対して両方を一緒に使うものではありません。

|  | 本プラグイン | MCP Bridge |
|---|---|---|
| セットアップ | `/plugin marketplace add` + `/plugin install` | 展開・インストーラ実行・MCP 設定ファイルの編集 |
| 使用するトランスポート | UAIP の HTTP API へ直接 | MCP over stdio → Bridge プロセス → UAIP の HTTP API |
| Claude Code 以外のクライアントに対応 | しない | する（Codex CLI・Claude Desktop・Cursor・Windsurf・Copilot — [接続方法](connections.md#mcp-bridge) 参照） |
| デモ版での利用 | 不可 — HTTP API は製品版限定 | 可 — MCP トランスポートはデモ版でも利用可能 |
| 配布 | 本リポジトリの Releases、`uaip-tools` マーケットプレイス | 本リポジトリの Releases、`UAIP-MCPBridge-<version>.zip` |

## 終了コード

コマンドスクリプトを実行するスキル（直接・サブスキル経由のどちらも）は、以下のいずれかを報告します。

| コード | 意味 |
|---|---|
| 0 | 成功し、すべての Artifact も保存できた |
| 1 | エディタが失敗を報告した（`Success: false`、または `CapabilityNotAvailable` / `PolicyViolation` / `InvalidParams` / `NotFound` / `CommandNotFound` / `TooManyRequests` 等のエラー） |
| 2 | 引数または入力の誤り（併用できない引数の組み合わせ、UE プロジェクトフォルダでない、`Saved/UAIP/Requests/` の外のリクエストファイル、不正な JSON、64 KiB を超える入力）。何も送信していない |
| 3 | 対象ポートのプログラムに到達できない、このプロジェクトの UAIP エディタと確認できない、または認証できない。何も実行されていない |
| 4 | タイムアウト。**結果は不明** — エディタがまだ処理している可能性がある。再送しないこと |
| 5 | コマンド（またはシナリオの全ステップ）は成功したが、1 つ以上の Artifact の取得・保存に失敗した |
| 6 | 応答を解釈できなかった。**結果は不明** |

`/uaip:scenario` で投入したシナリオについても同じコードが提出全体（1 コマンドの成功可否の代わりに、全ステップが
成功したか）を表し、終了コード 4 はエディタが 1800 秒の上限でシナリオを打ち切った場合も含みます
（[シナリオ実行 → レスポンスの形式](scenario.md#レスポンスの形式) 参照）。

## 本プラグインが `Saved/UAIP/` 配下に書き込むファイル

- **`Requests/`** — スキルがコマンドスクリプトに渡す前に、パラメータまたはシナリオのファイルを書き込む場所。
  スクリプトはファイルを読み込んだ後、スキルが保持を指示していない限り削除します。
- **`temp/`** — スキルが既に表示した応答や Artifact（画像・JSON・ログ）の保存コピー。後で読み返せるように
  保持されます。**いつでも削除して構いません** — 容量を空けるためだけの存在で、本プラグインはこの内容が
  残っていることに一切依存していません。
- **`raw/`** — テキスト Artifact に認証トークンの値が含まれていた場合にだけ使われます: 未加工の原本はここに、
  `temp/` 側のコピーは値がマスクされたものになります。`temp/` と同様、**いつでも削除して構いません** —
  トークン値がスキルの通常の表示コピーに残らないようにするためだけに存在します。
- **`EditorHttpAuthToken.txt`** と `InstanceSecrets/` 配下のポートごとのファイル — エディタ自身の資格情報・
  身元照合用ファイルです（[セキュリティ → Instance proof](security.md#instance-proof) 参照）。本プラグインは
  これらを書き込むことも削除することもありません。読めるものは誰でも本プラグインと同じ操作ができるので、
  他のローカルの秘密情報と同様に扱ってください。
- **`ClaudePluginLaunch.json`** — 直近に成功した起動のポートとシナリオ設定を記録します。これは、後続の
  コマンドが改めて指定しなくても同じ値を再利用できるようにするためだけのものです。接続を信頼するかどうかの
  判断に使われることは一切ありません — それは常に上記 [セキュリティ境界](#セキュリティ境界) で説明した
  コマンドごとの照合が行います。このファイルを削除しても、次回の起動が既定のポートに戻るだけです。
